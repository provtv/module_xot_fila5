# Story 5.28: Xot — governare i coverage harness nel gate PHPStan

## Story

Come owner della piattaforma di test, voglio definire quali coverage harness sono codice
canonico e imporre loro contratti statici espliciti, così che i moduli leaf possano
correggere i propri test senza copiare workaround divergenti.

## Baseline e riconciliazione

La baseline del 24 agosto attribuisce **706 findings a Xot**: 370
`staticMethod.alreadyNarrowedType`, 114 `argument.type`, 51 `method.nonObject` e 50 chiamate
Safe non gestite. Le story 5.18 duplicate dichiaravano una precedente regressione chiusa;
5.20 e 5.23 governano il verde durevole. Questa story è la tranche corrente e non riscrive
la loro storia: le supersede solo per il nuovo harness debt.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. È documentato, con evidenza di riferimenti e runner, se ciascun file di harness in scope
   è canonico, generato oppure eliminabile; nessun file è mantenuto solo per inerzia.
2. Gli harness canonici accettano e restituiscono tipi espliciti e non usano reflection,
   callback o valori `mixed` senza narrowing verificabile.
3. Le asserzioni `assertIs*`/`assertNotNull` già garantite dal tipo sono sostituite da
   verifiche semantiche oppure rimosse insieme al test privo di valore.
4. Tutti i 706 findings Xot correnti sono riclassificati: quelli nello scope sono risolti;
   i residui diventano tranche module-local separate con owned scope disgiunto.
5. Nessun `@phpstan-ignore`, baseline, exclude, nuovo `.neon`, Service o Action proxy viene
   introdotto; il comando letterale `analyse Modules` resta il gate.

## Testing

<!-- LOCKED. External dev tools must not edit Testing. -->

- Statico: PHPStan su ciascun file in scope, poi `Modules/Xot`, poi `Modules` cold.
- Pest: test mirati per l'harness mantenuto; nessun test deve invocare comandi distruttivi.
- Mutation review manuale: ogni assert deve poter fallire per una regressione concreta.
- Se un file è generato, verificare il producer e rigenerare in test; non patchare solo output.

## Dev Agent Record

### Stato di esecuzione (2026-08-24)

- Decisione producer/consumer: i quattro helper sono **canonici**, non generati e non
  eliminabili. `rg` rileva consumer in Xot e nei moduli Sigma, Ptv, Pdnd, UI, Job, Notify,
  Media, User, Incentivi, Performance, Progressioni e Indennita. I due test Unit sono
  consumer Xot canonici; le asserzioni puramente tautologiche sono state rimosse.
- `FilamentSchemaCoverage`: iterator boundary ristretto a `SplFileInfo`, risultati reflection
  verificati prima dell'uso, filtri verificati semanticamente come lista ordinata.
- `ModuleRemainingCoverage`: record mock popolati tramite API Eloquent, controller e
  class-string ristretti, Safe functions adottate, catch tautologici rimossi.
- `XotForkedInvoke`: exit status reale del child; eccezione/fork failure/timeout non sono più
  contati come successi. Enum static methods passano da `ReflectionMethod`.
- `XotExecuteCoverage50Test` e `XotHundredPercentCoverageTest`: rimossi assert sul solo tipo,
  API inesistenti/deprecate e successi fittizi nei catch; boundary LazyCollection e callback
  sono tipizzati.

### Verifiche

- `php -l`: PASS sui cinque file disponibili.
- PHPStan sui cinque file disponibili: **0 errori** (baseline locale precedente: 306).
- Pest mirato finale: **28 PASS, 3 risky, 1043 assertions**; 2 failure iniziali emerse

I 357 residui module-local richiedono story disgiunte: `tests/Unit` tautologie e catch;
`tests/Feature` boundary Pest; `tests` Safe/process; `app` contratti sorgente (5 errori).
