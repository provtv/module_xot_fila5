# XOT-5.34 — disposition degli sweep zero-gap

## Story

Come maintainer Xot, voglio rimuovere o trasformare gli sweep nati per “uccidere zeri”, così che
la suite conservi soltanto specifiche in grado di rilevare mutazioni.

## Acceptance Criteria

<!-- LOCKED -->
1. I 41 finding correnti dei sette file owned sono risolti.
2. Classi astratte, costruttori, static call e proprietà rispettano i consumer reali.
3. Ogni test ha un'aspettativa comportamentale; i coverage-only sono eliminati con disposition.
4. Nessuna suppression, baseline, tautologia o modifica fuori scope.

## Tasks / Subtasks

- I sette file ora contengono nove test mutation-sensitive su: default metatag, payload/status
  JSON, URL fallback, opzioni AnalyzeComponents, selezione handler per tipo eccezione, parametri
  route, round-trip e guard del PhoneCast, provenance ComponentFileData.

  nessuna proprietà o relazione finta è stata introdotta.
