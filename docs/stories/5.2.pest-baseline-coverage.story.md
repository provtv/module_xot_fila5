# 5.2: Pest test suite: init + baseline coverage

**Story ID:** 5.2
**Epic:** 5 — Code Quality & Infrastructure
**Slug:** pest-baseline-coverage
**Status:** backlog

## Story

As the tech lead accountable for the test-coverage quality gate,
I want a measured Pest coverage baseline with the four critical paths (RBAC, Scheda approval, Sigma sync, email) demonstrably tested,
so that the project can prove where it stands against the 85% target and the 82% CI-fail floor before other epics ship features on top of untested code.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. `cd laravel && php artisan test --coverage` runs successfully and produces a coverage percentage report, establishing the current measured baseline. [Source: prd.md#NFR-CQ-002 — "Tools: Pest + Xdebug coverage reports"]
2. Overall coverage across `laravel/` is at or above 82% when measured with `php artisan test --coverage --min=82`. [Source: prd.md#NFR-CQ-002 — "CI gate: fail if coverage drops below 82%"]
3. Each of the four critical paths named by NFR-CQ-002 — RBAC, Scheda approval, Sigma sync, email — has at least one passing Pest Feature test exercising it. [Source: prd.md#NFR-CQ-002 — "Critical paths: 100% (RBAC, Scheda approval, Sigma sync, email)"]
4. No test added or modified in this story uses `RefreshDatabase`, `DatabaseMigrations`, `migrate:fresh`/`migrate:refresh`, or `truncate()`; all new tests use `DatabaseTransactions` for isolation. [Source: docs/wiki/rules/testing_no_refresh_database_critical.md — "isolamento con `DatabaseTransactions`... mai `RefreshDatabase`, `DatabaseMigrations`"]
5. The pre-existing Pest suite (`laravel/tests/Feature/**`, `laravel/tests/Unit/**` as they exist before this story) still passes after this story's additions — no regression introduced. [Inference — grounded in the observed fact that `laravel/tests/Pest.php` and an existing Feature/Unit suite are already present in this repo]

## Tasks / Subtasks

- [ ] Run `cd laravel && php artisan test --coverage` and record the current baseline percentage (AC: #1)
- [ ] Cross-reference the coverage report against RBAC, Scheda approval, Sigma sync, and email code paths to identify untested branches (AC: #3)
- [ ] Write/extend Pest Feature tests for each critical path lacking coverage, using `DatabaseTransactions` and `Mail::fake()`/`Notification::fake()`/HTTP fakes where external systems are involved (AC: #3, #4)
- [ ] Extend Unit/Feature tests elsewhere in the codebase to close the gap toward the 82% floor (AC: #2)
- [ ] Re-run `php artisan test --coverage --min=82` and confirm pass (AC: #2)
- [ ] Run the full suite once more and confirm the pre-existing tests are unaffected (AC: #5)

## Testing

<!-- LOCKED. External dev tools must not edit Testing. -->

- **Test type:** Pest Feature tests for the four critical paths (RBAC permission checks, Scheda approval state transition, Sigma sync job, email/notification dispatch); Unit tests for isolated logic elsewhere; coverage measured via Xdebug through `php artisan test --coverage`.
- **Fixtures:** model factories for `User` with each role assigned (reuse the pattern from `Modules/User/tests/Feature/Rbac/*` if landed), a `Scheda` (or stub) factory in an approval-eligible state, a fake/mocked Sigma HTTP client (never call the real Sigma WebService in tests), `Mail::fake()`/`Notification::fake()` for email assertions.
- **Scenarios to prove each AC:**
  - AC #1: coverage command exits 0 and prints a percentage.
  - AC #2: `--min=82` flag causes the command to fail below threshold and pass at/above it — confirm post-fix run is at/above 82%.
  - AC #3: one passing test per critical path, asserting the actual business outcome (e.g. evaluator can create Scheda, approval transitions status, sync job persists records, email is queued/sent).
  - AC #4: `grep -rl "RefreshDatabase\|DatabaseMigrations\|truncate(" laravel/tests` on newly added files returns nothing.
  - AC #5: full suite run, diff pass/fail count against pre-story baseline.
- **Edge cases:** Sigma API timeout/error response (must be faked, not hit live); email queue failure path; RBAC test for a user with no role assigned; Scheda approval attempted twice (idempotency).
