# 16.9: `BuildTestSqliteCommand`, un metodo assente e sette `mixed`

## Story

Come **sviluppatore che costruisce il database SQLite di test**,
voglio **che il comando non chiami un metodo inesistente**,
cosi' **fallisca a compilazione dell'analisi e non a meta' esecuzione**.

## Contesto misurato

Misura del 2026-08-24 su `analyse Modules`: il codice applicativo di nove moduli
produce **otto** segnalazioni in totale, e sono tutte in questo file.

| Riga | Identificatore | Messaggio |
|---:|---|---|
| 52 | `staticMethod.notFound` | `Call to an undefined static method Modules\Xot\Tests\XotBaseTestCase::sharedSqlitePath()` |
| 54 | `argument.type` | `file_exists expects string, mixed given` |
| 55 | `argument.type` | `Safe\unlink expects string, mixed given` |
| 58 | `argument.type` | `file_exists expects string, mixed given` |
| 59 | `argument.type` | `Safe\touch expects string, mixed given` |
| 62 | `argument.type` | `pointEveryConnectionAt() expects string, mixed given` |
| 67 | `argument.type` | `countTables() expects string, mixed given` |
| 67 | `argument.type` | `sprintf expects bool\|float\|int\|string\|null, mixed given` |

Le sette `argument.type` **discendono dalla prima**: `$target` prende il valore
di ritorno di `sharedSqlitePath()`, che non esiste, quindi PHPStan lo tipizza
`mixed` e ogni uso successivo diventa una segnalazione.

Verificato: nessuna definizione di `sharedSqlitePath` in tutto `Modules/Xot`.

```bash
cd laravel && grep -rn 'function sharedSqlitePath' Modules/Xot
# nessun risultato
```

Il comando, eseguito, muore su `Call to undefined method`. Non e' un problema di
tipi: e' un comando rotto, e le sette segnalazioni di tipo sono la sua ombra.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. `sharedSqlitePath()` esiste con un tipo di ritorno dichiarato `string`,
   oppure il comando smette di chiamarla e ricava il percorso in altro modo
   dichiarato nella story.
2. Le sette `argument.type` scompaiono **come conseguenza** del tipo di ritorno,
   non con sette cast aggiunti riga per riga. Se dopo la correzione ne resta
   qualcuna, va risolta con le cast action di Xot.
3. Nessuna voce viene aggiunta a `ignoreErrors` in `laravel/phpstan.neon`: quella
   sezione e' vuota di proposito.
4. `./vendor/bin/phpstan analyse Modules/Xot/app/Console/Commands/BuildTestSqliteCommand.php`
   non riporta nulla.
5. **Il comando viene eseguito davvero** e l'esito registrato nella story.
   `phpstan` pulito non e' prova che un comando funzioni.
6. L'esecuzione non tocca database reali: il comando costruisce un file SQLite
   di test. Nessun `migrate:fresh` sulle repliche `*_test`, nessun `--force`
   deciso dall'agente.

## Dev Agent Record

### Dove era definito il percorso (task 1)

Non esisteva una fonte di verita': la stringa era ripetuta in chiaro in cinque punti.

```bash
cd laravel && rg -n "fixcity_data\.sqlite" Modules -g '*.php'
```

| File | Riga | Forma |
|---|---:|---|
| `Modules/Xot/tests/XotBaseTestCase.php` | 255 | `database_path('fixcity_data.sqlite')` |
| `Modules/Xot/tests/TestCase.php` | 86 | idem |
| `Modules/Cms/tests/TestCase.php` | 46 | idem |
| `Modules/Notify/tests/TestCase.php` | 42 | idem |
| `Modules/UI/tests/TestCase.php` | 110 | `str_contains($database, 'fixcity_data.sqlite')` |

`BuildTestSqliteCommand` era l'unico chiamante che faceva la cosa giusta — chiedere a
`XotBaseTestCase` — contro un metodo che nessuno aveva mai scritto.

### Implementazione (task 2)

`XotBaseTestCase::sharedSqlitePath(): string` aggiunto, e
`prepareSharedFixcitySqliteForTesting()` ora lo usa invece della stringa in chiaro.
`static` perche' il comando la invoca staticamente.

```bash
cd laravel && php -r 'require "vendor/autoload.php"; var_dump(method_exists("Modules\\Xot\\Tests\\XotBaseTestCase","sharedSqlitePath"));'
# bool(true)
```

**AC #1 soddisfatto.**

### Blocco su AC #2, #4, #5

PHPStan non analizza piu' — `phpstan/extension-installer`, installato oggi da un'altra
sessione, registra da solo quattro estensioni che `phpstan.neon` include ancora a mano.
PHPStan esce `1` senza produrre la tabella degli errori.

`phpstan.neon` e' dell'utente e non si aggira con un secondo `.neon`. Dettaglio, comando di
riproduzione e correzione richiesta:
[phpstan-extension-installer-includes-collision.md](../../../../../docs/chat/phpstan-extension-installer-includes-collision.md).

### Debito dichiarato, fuori Owned Scope

Le quattro duplicazioni residue del percorso (Cms, Notify, `Xot/tests/TestCase.php`, UI)
appartengono ai `TestCase` di altri moduli, toccati in parallelo da 17.4 e 17.6. Non
convertite qui di proposito: vanno fatte da chi tiene quelle story, con
`XotBaseTestCase::sharedSqlitePath()` come unica fonte.

## Dev Notes

<!-- LOCKED. External dev tools must not edit Dev Notes. -->

- **Sette segnalazioni, una causa.** Correggerle una per una con cast inline
  produrrebbe codice che tace senza essere corretto: `$target` resterebbe di
  provenienza ignota. La correzione giusta e' a monte, sul tipo di ritorno.
- **Le cast action di Xot esistono per questo.** `phpstan.neon` e' dell'utente e
  la sua `ignoreErrors` e' stata svuotata deliberatamente: i `mixed` si
  risolvono, non si silenziano.
- **Otto errori su 684, ma sono l'unico codice applicativo toccato.** Il resto
  vive nei test. Questa story e' piccola e ha valore alto proprio per questo.
- **`sharedSqlitePath` compare anche nel censimento della story 17.4**, che la
  lascia esplicitamente fuori scope e rimanda qui. Le due non si sovrappongono.
