# 5.11: Bootstrap Pest condiviso senza `require_once`

**Story ID:** 5.11
**Epic:** 5 — Code Quality & Infrastructure
**Slug:** pest-shared-bootstrap-without-require
**Status:** done  
**Completed:** 2026-08-19

## Story

Come **agente che scrive test in un modulo qualsiasi**,
voglio **raggiungere gli helper condivisi di Xot senza includere un file a mano**,
così **il bootstrap di un modulo non contiene infrastruttura, e PHPStan vede gli helper come
simboli normali invece che come funzioni globali caricate a runtime**.

Oggi quattro moduli su diciotto aprono il proprio `tests/Pest.php` con

```php
require_once __DIR__.'/../../Xot/tests/XotBasePest.php';
```

Il pattern funziona ma paga tre prezzi. È un path relativo fragile che risale due livelli di
filesystem e si rompe se un modulo cambia posto. Obbliga ogni helper a essere una funzione
globale protetta da `function_exists()`, perché nella run full-suite Pest carica il `Pest.php`
di tutti i moduli nello stesso processo e due dichiarazioni uguali sarebbero un fatal
`cannot redeclare`. E lascia gli helper fuori dall'autoload, quindi invisibili a chi legge il
codice partendo dalla classe.

La documentazione Pest (`https://pestphp.com/docs/custom-helpers`) prevede il caricamento
automatico di `tests/Pest.php`, `tests/Helpers.php` e `tests/Helpers/`, ma quel meccanismo è
relativo alla **directory di test configurata**, cioè una sola: non copre diciotto
`Modules/<Mod>/tests/`. Non esiste quindi una via Pest-nativa per questo layout.

La via che il layout offre già è l'autoload PSR-4: `Modules\Xot\Tests\` è mappato su
`Modules/Xot/tests` in `vendor/composer/autoload_psr4.php`. Una classe in quel namespace è
raggiungibile da qualunque modulo senza include, senza guardie e senza path relativi.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. Nessun `Modules/<Mod>/tests/Pest.php` contiene più `require_once` verso `XotBasePest`.
2. Gli helper condivisi sono raggiungibili via autoload PSR-4, senza voci in
   `composer.json` → `autoload.files` (AD-3: il contratto di autoload resta chiuso).
3. Nessun helper condiviso è più una funzione globale protetta da `function_exists()`: la
   guardia sparisce insieme alla causa che la rendeva necessaria.
4. Il comportamento degli helper non cambia: stesse asserzioni, stessi tipi di ritorno,
   stessi generics. Nessuna firma persa — `git diff | grep "^-.*function "` va letto e ogni
   riga giustificata dalla migrazione, non da una dimenticanza.
5. `./vendor/bin/phpstan analyse <file> --no-progress --memory-limit=-1` è verde sul file
   nuovo e su ogni `Pest.php` toccato, con `laravel/phpstan.neon` **non modificato** e senza
   creare altre configurazioni `.neon` (AD-1, AD-2).
6. `php -l` su ogni file toccato; PHPMD e PHPInsights senza rilievi nuovi rispetto alla copia
   `git show HEAD:`.
7. Ogni file è lockato prima dell'edit e sbloccato dopo.
8. `Modules/Xot/docs/` documenta il pattern nuovo, e la regola `AD-5` della spine è aggiornata
   in luogo mantenendo l'ID stabile.
