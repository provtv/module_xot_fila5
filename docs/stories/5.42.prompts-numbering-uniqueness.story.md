# XOT-5.42 — un numero, un prompt

## Story

Come agente che riceve l'istruzione «carica il prompt 11», voglio che quel numero risolva a
**un** file e che il nome di quel file dica cosa contiene, così da non eseguire istruzioni
su PHP Insights credendo di star facendo PHPStan.

## Il numero è un indirizzo

`bashscripts/docs/prompts` non è documentazione: è il sistema operativo degli agenti. Il suo
`README.md` fissa la regola in una riga — **«Un numero = un file»** — e la ragione sta nel
modello di caricamento: i prompt numerati **non si preloadano**, si chiedono per numero.

Un numero duplicato è un indirizzo che risolve a due cose diverse a seconda di come il
filesystem ordina la directory.

## Evidenza misurata (2026-08-24)

50 prefissi numerici, **14 con collisione**, 33 file coinvolti.

E il difetto peggiore: **13 file iniziano con `# FROM: <origine>.md`** — copie automatiche
in cui il contenuto è quello dell'origine e il **nome mente**.

| File | Contenuto reale |
|---|---|
| `11-phpstan.md` | **PHP Insights** |
| `10-ponytail-audit.md` | gitmodules |
| `17-ponytail.md` | gitmodules |
| `04-filament.md` | «Datas, mai DTO» |
| `06-filament.md` | audit Filament |
| `18-github.md` | vecchia versione del prompt issue |
| `05-widget` · `08-ui` · `10-test` · `15-bmad` · `16-git` · `19-docs` · `20-filesystem` | copia dell'origine omonima |

Sovrapposizione lessicale con l'origine: 97-99% su sette di questi.

Collisioni **vere** (due argomenti diversi che condividono un numero), da trattare a parte:
01, 06, 07, 17.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. Nessun prefisso numerico è usato da più di un `.md` in `bashscripts/docs/prompts`.
2. Nessun file conserva l'intestazione `# FROM: <file>.md`. Per ciascuno dei 13 la
   decisione è tracciata nel Dev Agent Record: rimosso perché il contenuto è nell'origine,
   oppure conservato con una motivazione.
3. Nessun contenuto perso: per ogni file rimosso, il suo corpo è raggiungibile
   nell'origine, verificato per confronto — non per dimensione.
4. Le quattro collisioni vere (01, 06, 07, 17) sono risolte rinumerando il file **più
   recente** al primo slot libero, oppure fondendo se i due prompt trattano lo stesso tema.
5. `INDEX.md` e `README.md` della cartella riflettono lo stato finale; nessun link interno
   punta a un file rimosso.
6. Esiste `bashscripts/quality-gates/verify-prompts-numbering.sh` che fallisce su un
   prefisso duplicato o su un'intestazione `# FROM:`, verificato in negativo.

## Dev Notes

<!-- LOCKED. External dev tools must not edit Dev Notes. -->

- **Il generatore non è nel repository.** Cercato in `bashscripts` fra `.sh`, `.php`, `.py`:
  nessuno script produce `# FROM:`. Le copie le ha fatte un agente, non un tool committato:
  il rimedio è una regola più un gate, non la cancellazione di uno script.
- **Verificare i link entranti prima di rimuovere.** I prompt si citano fra loro e
  dall'`INDEX.md`; un file rimosso senza riscrivere i riferimenti lascia link rotti.
- **`01-architecture-patterns.md` pesa 107 KB.** Un prompt on-demand di quella dimensione
  costa più di quanto risparmi. Non è nello scope di questa story, ma va segnalato.
- **Un file `FROM:` non è sempre da buttare.** Se il nome corto era la destinazione voluta
  di una rinomina, la soluzione è portarci il contenuto giusto, non cancellarlo. Per i 13
  casi qui l'origine esiste e ha un nome più descrittivo: si cancella la copia.

## Testing

<!-- LOCKED. External dev tools must not edit Testing. -->

- **Unicità**: nessun prefisso `NN-` compare due volte fra i `.md` della cartella.
- **Nomi onesti**: `/bin/grep -l '^# FROM: ' *.md` non restituisce nulla.
- **Conservazione**: per ogni file rimosso, il corpo senza l'intestazione `FROM:` coincide
  con l'origine, confrontato riga per riga.
- **Link**: nessun link relativo in `bashscripts/docs/prompts/**` punta a un file rimosso;
  conteggio dei rotti prima e dopo, non deve peggiorare.
- **Gate in negativo**: creando `11-doppione.md` il gate esce `1`; rimosso, esce `0`.

## Dev Agent Record

### Esecuzione 2026-08-24 — Claude (Opus 5)

**Correzione importante al piano: le 13 copie NON si possono cancellare.**

L'AC #3 chiede di verificare che il corpo di ogni copia sia nell'origine prima di
rimuoverla. La verifica **ha fallito su tutte e 13**: ogni copia ha da 2 a 31 righe che
nell'origine non ci sono. Guardandole, la storia è diversa da quella ipotizzata nel
brainstorming:

```text
--- MERGED FROM: 11-merged.md ---
--- MERGED FROM 11-phpstan-level-max.md ---
```

Non sono copie di una rinomina lasciata a metà: sono il **prodotto di una campagna di
fusione**. Più prompt sono stati concatenati in un file solo, e l'intestazione `# FROM:`
registra la prima sorgente delle tante.

Il caso che chiude la questione è `17-ponytail.md`. Il `FROM:` dice
`17-gitmodules-path-iteration.md`, e infatti comincia col prompt gitmodules — ma più
avanti contiene:

```text
--- MERGED FROM 17-ponytail-audit.md ---
# Prompt — Controlla e migliora Ponytail
Analizza come Ponytail viene usato per individuare codice morto o inutilizzato.
```

Contenuto su Ponytail che **nell'origine non esiste**. Cancellare il file per «è una copia»
avrebbe perso l'unico prompt su Ponytail del repository.

**Perché il nome sembra mentire.** Non mente: descrive l'**ultimo** segmento fuso, mentre
l'`H1` in testa descrive il **primo**. `11-phpstan.md` comincia con PHP Insights e più sotto
ha il segmento PHPStan. Il file non è misnamed: è **bicefalo**.

#### Cosa serve davvero

Il lavoro non è una cancellazione ma uno **scorporo**: separare i segmenti `MERGED FROM`,
dare a ciascuno il file che il suo nome promette, e togliere i doppioni veri.

| Numero | Segmenti da separare |
|---|---|
| 11 | PHP Insights · PHPStan level max |
| 17 | gitmodules path-iteration · gitmodules sync · Ponytail audit |
| 19 | docs second brain · github discussions |
| 10 | Pest XotBaseTest · Ponytail audit |
| 04 · 05 · 06 · 08 · 15 · 16 · 18 · 20 | da mappare uno per uno |

**Non l'ho fatto in questa sessione**: è un lavoro editoriale su 13 file che richiede di
leggere ogni segmento e decidere dove va, e la priorità dell'utente si è spostata sul gate
PHPStan. La story resta aperta con il piano corretto.

#### Fatto

- Censimento: 50 prefissi, 14 collisioni, 33 file; 13 intestazioni `# FROM:`.
- Ricerca del generatore: **nessuno script committato** in `bashscripts` produce quelle
  intestazioni. Le ha scritte un agente. Il rimedio è la regola più il gate, non la
  rimozione di un tool.
- Verifica di conservazione **prima** della rimozione, che ha impedito la perdita di
  contenuto. È l'unico motivo per cui questa nota esiste invece di un elenco di file
  cancellati.

#### Lezione

Il brainstorming aveva un'ipotesi plausibile — «rinomina lasciata a metà» — e sbagliata.
A salvarla non è stato il ragionamento ma **l'AC che imponeva di verificare prima di
cancellare**. Un piano che dice «cancella le copie» senza un criterio per dimostrare che
sono copie è un piano che perde dati.
