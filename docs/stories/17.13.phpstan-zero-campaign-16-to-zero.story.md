# 17.13: PHPStan `analyse Modules` da 16 a 0 errori (non deprecati) senza toccare phpstan.neon

**Story ID:** 17.13
**Epic:** 17 — PHPStan Zero Campaign
**Slug:** phpstan-zero-campaign-16-to-zero
**Status:** todo
**Created:** 2026-08-25
**Updated:** 2026-08-25

## Story

Come **tech lead responsabile della qualità su `dev`**,
voglio **`./vendor/bin/phpstan analyse Modules` che termina con `[OK] No errors` sugli errori non deprecati**,
così **il gate PHPStan della story può essere reso bloccante senza rendere rossa ogni PR aperta**.

Stato di partenza: l'analisi termina con 16 errori non deprecati (function.notFound, argument.type, static, offset, class.not, pest.expectation.redundant, variable.undefined, return.type, function.already, argument.template, ternary.always, method.static, method.not, binary, assign.property).

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. `cd laravel && php -d memory_limit=-1 ./vendor/bin/phpstan analyse Modules --no-progress` termina con `[OK] No errors` per gli errori non deprecati.
2. `laravel/phpstan.neon` non è modificato: nessun `ignoreErrors` aggiunto, nessuna baseline generata, nessun `--level` da riga di comando. [Source: docs/wiki/rules/phpstan-neon-immutable.md]
3. Nessun errore è stato spento con `@phpstan-ignore`, `@var` inline, `assert()`, cast di comodo o allargamento di tipo di ritorno. Ogni correzione agisce sulla causa.
4. Il comando di verifica è eseguibile: nessun fatal error PHP o errore di parsing che blocca l'analisi prima di produrre i risultati.
5. Ogni storia BMAD associata a questo lavoro deve avere una sezione `## GitHub (tracciamento)` con URL puntuali di issue e discussion del repo DEL MODULO.
