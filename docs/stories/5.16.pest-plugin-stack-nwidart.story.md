# Story 5.16: Stack plugin Pest 5 — nwidart + `composer update -W`

## Story

Come **architect / manutentore toolchain**,
voglio **i sei plugin Pest richiesti installati via modulo Xot e risolti con merge-plugin**,
così **`laravel/composer.json` resta minimo** e ogni agente sa che dopo ogni edit ai
`Modules/*/composer.json` deve eseguire `cd laravel && composer update -W`.

## Perché nwidart cambia il workflow

Con [nwidart/laravel-modules](https://github.com/nwidart/laravel-modules) le dipendenze dev
vivono in `Modules/<Mod>/composer.json`. Il merge-plugin le unisce al lock della root
**solo** quando si risolve da `laravel/`:

```bash
cd laravel
composer update -W    # -W = --with-all-dependencies
```

**Vietato:** `composer require pestphp/...` dalla root — scriverebbe in `laravel/composer.json`.

## Cosa resta minimo in `laravel/composer.json`

- `require`: framework, nwidart, sentry, … — **nessuna** riga Pest
- `require-dev`: solo `phpmd/phpmd` (tool root)
- `config.allow-plugins`: `pestphp/pest-plugin`, `phpstan/extension-installer`, merge-plugin

## Acceptance Criteria

1. I sei plugin + `rector/rector` + `extension-installer` in Xot `require-dev` — **zero** Pest in root require-dev.
2. `cd laravel && composer update -W` completato senza rimozioni dev critiche (mockery, pint, ide-helper ok).
3. Verifica funzionale:
   - `./vendor/bin/rector --version`
   - `php artisan pest:test` / `pest:dataset`
   - `./vendor/bin/pest --profanity` → PASS
   - `Pest\Faker\fake('it_IT')` → Generator
4. `laravel/composer.json` invariato sulle dipendenze Pest.
5. Doc aggiornata: `pest-official-plugins.md` con workflow `-W` e link GitHub.
6. `laravel/phpstan.neon` **non modificato** dagli agenti.
