## Story

Come **tech lead quality multi-modulo**,
voglio **`./vendor/bin/phpstan analyse Modules` verde a livello max con `tests/` in perimetro**,
così **il gate 03-quality-gates torna bloccante dopo la story 5.7 e i plugin Pest/PHPStan sono utilizzabili senza regressioni**.

## Perché (regressione)

La story 5.7 chiudeva ~923 errori con `app/` only. Oggi `laravel/phpstan.neon` ha
`excludePaths: ./*/tests/*` **commentato** (solo l'utente modifica il neon): l'analisi include
`Modules/*/tests/` e riporta **~923 errori** distribuiti su 19 moduli (2026-08-19).

| Modulo | Errori (snapshot) |
|--------|-------------------|
| Xot | 208 |
| IndennitaResponsabilita | 149 |

| Progressioni | 109 |

| Rating | 62 |
| Sigma | 62 |
| … | … |
| Lang | 2 → **0** (lotto 1) |
| Job | 4 → **0** (lotto 1) |

Cluster dominanti in Xot: `method.deprecated` (Filament/Spatie Data), `method.nonObject`,
`function.notFound` (helper Pest), `pest.*` (plugin non attivo in neon finché utente non sblocca includes).

## Acceptance Criteria

1. `cd laravel && ./vendor/bin/phpstan analyse Modules --no-progress --memory-limit=-1` → `[OK] No errors`.
2. **`laravel/phpstan.neon` non modificato dagli agenti** — nessun `.neon` aggiuntivo, nessuna baseline.
3. Nessuna soppressione `@phpstan-ignore` / `@var mixed` / cast di comodo; narrowing reale ([5.10](./5.10.mixed-narrowing-campaign.story.md)).
4. **Nessuna cartella `tests/Support/`** — helper in `XotBasePest` (PSR-4) o metodi su `TestCase` modulo.
5. Bootstrap Pest: niente `require_once` cross-modulo; pilota `pest()->extend(TestCase::class)` con ignore inline su `Pest.php` **dopo** gate verde modulo (pattern [Activity 3.10](../../Activity/docs/stories/3.10.activity-pest-extend-bootstrap.story.md)).
6. Plugin stack verificato via `composer show '*phpstan*'` e `composer show 'pestphp/pest-plugin-*'` dopo `composer update -W`.
7. Coverage modulo lavorato: **+10%** misurato con `phpunit.xml` di modulo (`-c Modules/{Mod}/phpunit.xml`).
8. Docs modulo + `03-quality-gates.md` aggiornati con learnings verificati.
9. Remote modulo sincronizzati (`git remote -v` → push su **tutti** i remote).

## Dev guardrails (LOCKED)

| Regola | Dettaglio |
|--------|-----------|
| Neon | Solo `laravel/phpstan.neon`; zero file `.neon` nuovi |
| Test | Solo Pest; `uses(TestCase::class)` per file; no PHPUnit class-based |
| DB test | MySQL `*_test`; `DatabaseTransactions`; no SQLite |
| Mixed | Ultima spiaggia — union + `is_*` + generics |
| Composer | Dipendenze Pest/PHPStan in `Modules/Xot/composer.json`; root minimo; `composer update -W` |
| Lock | FLVP prima di ogni edit condiviso |

## Comandi gate (modulo)

```bash
cd laravel
./vendor/bin/phpstan analyse Modules/{Mod} --no-progress --memory-limit=-1
tools/phpmd.sh Modules/{Mod}/app text ../phpmd.xml
tools/phpinsights.sh analyse Modules/{Mod}/app --no-interaction
./vendor/bin/pest -c Modules/{Mod}/phpunit.xml --no-coverage  # se DB up
```

## Architecture compliance

- ADR-017: `pest()->extend()` solo con `@phpstan-ignore method.internalClass` su riga singola in `Pest.php`.
- ADR-019: `phpstan.neon` immutabile per agenti.
- nwidart merge-plugin: stack dev in modulo Xot, non in root.
