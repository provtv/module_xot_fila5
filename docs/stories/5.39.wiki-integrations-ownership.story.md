# XOT-5.39 — restituire ai moduli la loro documentazione

## Story

Come agente che deve rispondere a «come funziona X nel modulo Notify», voglio **una sola**
versione di quel documento, nel repository che possiede X, così da non dover scegliere a
caso fra due risposte diverse che nessuna delle due dichiara di essere la copia.

## Il problema, misurato

`docs/wiki/integrations/modules/` contiene **1308 file `.md`** per quattro moduli, più
**20 file sciolti** `<modulo>-*.md` in `docs/wiki/integrations/`. Totale **1328**.

Confronto con la `docs/` del modulo proprietario:

| Modulo | file | identici | uguali tranne frontmatter | corpo diverso | solo qui |
|---|---:|---:|---:|---:|---:|
| lang | 218 | 165 | 5 | 38 | 10 |
| notify | 478 | 23 | 227 | 197 | 31 |
| user | 362 | 252 | 56 | 4 | 50 |
| xot | 250 | 35 | 178 | 27 | 10 |
| **totale** | **1308** | **475** | **466** | **266** | **101** |

I 20 sciolti: media 4, job 3, activity 2, rating 2, tenant 2, e uno ciascuno per incentivi,
indennitacondizionilavoro, pdnd, performance, progressioni, ptv, sigma.

**Le cartelle `Modules/<Mod>/docs/wiki/integrations/` non esistono ancora**: vanno create.

## Perché è un problema, e perché la mossa originale non era stupida

Il danno peggiore sono i **266 file con corpo diverso**: due versioni della stessa pagina,
nessuna che dichiari di essere derivata. Chi cerca trova due risposte e non ha criterio.

Gli altri tre motivi:

1. **I moduli sono repository separati.** Un modulo clonato altrove perde tutto ciò che sta
   nella `docs/` del progetto ospite: la documentazione smette di viaggiare col codice.
2. **La root è un indice, non un magazzino** — regola di progetto, non opinione.
3. **La ricerca non ha bisogno della copia**: la collection qmd `ptvx-modules-wiki`
   indicizza già `laravel/**`.

La consolidazione originale (commit `109c2f7a63`, «Nuclear consolidation: 1.667 file
consolidati → wiki/») rispondeva però a un bisogno vero: con 16.000 file sparsi in 21
repository, un punto unico dove guardare serve. Ha risolto un problema di **ricerca** con
uno strumento di **archiviazione**. Oggi il problema di ricerca ha uno strumento suo, e
quello che serve al posto delle copie è un **indice con i link**.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. `docs/wiki/integrations/modules/` non esiste più. Al suo posto, in
   `docs/wiki/integrations/README.md`, un indice con link relativi ai moduli proprietari.
2. Ogni file migra nel repository del modulo, sotto
   `laravel/Modules/<Mod>/docs/wiki/integrations/`, mantenendo la struttura di
   sottocartelle che aveva.
3. **Nessun contenuto perso.** Per ogni file rimosso dalla root vale una di queste, e la
   scelta è tracciata nel Dev Agent Record:
   - byte-identico a un file del modulo → rimosso;
   - corpo identico ma con frontmatter → il frontmatter è **portato sull'originale** del
     modulo prima della rimozione;
   - corpo diverso → merge **a mano** nel file del modulo, un file per volta;
   - assente nel modulo → spostato.
4. I 20 file sciolti `<modulo>-*.md` sono spostati nel modulo, **senza** il prefisso
   ridondante (`media-ffmpeg-integration.md` → `Modules/Media/docs/wiki/integrations/ffmpeg-integration.md`).
5. Nessun link interno resta rotto: i riferimenti ai percorsi vecchi sono riscritti, e la
   verifica è per risoluzione del path, non per sostituzione testuale del basename.
6. Esiste `bashscripts/quality-gates/verify-docs-ownership.sh`, che fallisce se
   `docs/wiki/` torna a contenere una cartella per modulo, ed è verificato in negativo.
7. La regola è nel second brain in `docs/wiki/rules/module-docs-ownership.md`.
8. `qmd` reindicizzato; una ricerca su un argomento migrato restituisce **un solo** file,
   quello del modulo.
9. `verify-llm-wiki.sh` resta `PASS` e `phpstan analyse Modules` resta a 0.

## Dev Notes

<!-- LOCKED. External dev tools must not edit Dev Notes. -->

- **I 466 "solo frontmatter" sono un regalo, non un problema.** Quel frontmatter è stato
  aggiunto in root il 24 agosto 2026 (759 file, XOT-5.37); è esattamente ciò che manca ai
  file del modulo perché qmd li indicizzi. Va portato sull'originale, non buttato con la
  copia.
- **Mai una riscrittura automatica di massa sulle docs.** È ciò che ha prodotto il fatal
  error del 2026-08-05 su `Modules`.
  [Source: docs/wiki/rules/docs-naming-audit-modules-themes.md]
- **La riscrittura dei link non è meccanica.** Lo stesso basename può essere il nome
  canonico legittimo di un file diverso in un altro modulo: una sostituzione globale
  ripunta silenziosamente quei link. Si risolve il path, non si sostituisce la stringa.
- **Rimisurare al momento dell'azione.** Fra la misura e l'esecuzione un altro agente può
  aver toccato gli stessi file: l'hash va riverificato prima di ogni rimozione.
- **`grep` e `find` sono funzioni di shell** che filtrano i path gitignored: nei censimenti
  e nei gate usare `/bin/grep` e `/usr/bin/find`.
  [Source: laravel/Modules/Xot/docs/stories/5.37.zero-conflict-markers-repo-wide.story.md]
- **Ogni modulo è un repository separato**: gli spostamenti attraversano un confine di
  repo. `git mv` non funziona fra repository diversi — si copia, si verifica, si rimuove,
  e si committa **due volte**, una per repo.

## Testing

<!-- LOCKED. External dev tools must not edit Testing. -->

- **Conservazione**: per ogni file rimosso, il suo contenuto è raggiungibile nel modulo.
  Verifica per hash sugli identici; per corpo normalizzato (senza frontmatter) sui
  solo-frontmatter; a mano sui corpo-diverso.
- **Conteggio**: `/usr/bin/find docs/wiki/integrations -name '*.md' | wc -l` scende a 1
  (il solo `README.md`); la somma dei `Modules/*/docs/wiki/integrations/**` sale
  coerentemente.
- **Link**: ogni link relativo nei file toccati risolve a un file esistente. Verifica per
  risoluzione, con conteggio dei rotti prima e dopo — non deve peggiorare.
- **Ricerca**: `bash bashscripts/docs/llm-wiki-qmd.sh search "<argomento migrato>"`
  restituisce un solo percorso, nel modulo.
- **Gate**: `verify-docs-ownership.sh` esce `1` se si ricrea a mano
  `docs/wiki/integrations/modules/pippo/x.md`, e `0` dopo averla rimossa.
- **Non regressione**: `verify-llm-wiki.sh` `PASS`; `phpstan analyse Modules` 0 errori.
