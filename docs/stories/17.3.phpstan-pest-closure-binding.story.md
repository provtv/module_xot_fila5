## Story

Come **sviluppatore che verifica il proprio lavoro con PHPStan**,
voglio **che `$this` dentro un closure Pest non risulti indefinito**,
cosi' **161 segnalazioni smettano di coprire i difetti veri**.

## Contesto misurato

Misura del 2026-08-24 su `analyse Modules`:

| Identificatore | Occorrenze |
|---|---:|
| `function.void` | 101 |
| `variable.undefined` | 60 |

```
Undefined variable: $this
Result of function describe (void) is used
Result of function uses (void) is used
```

Distribuzione: Lang 39, Xot 38, Media 26, Activity 17, User 12, Job 11,
Notify 11, UI 7.

Causa: Pest lega i closure di `it()`, `test()` e `describe()` al TestCase a
runtime. PHPStan non lo sa.

## Quello che ancora non si sa

`laravel/phpstan.neon` include `vendor/pestphp/pest/extension.neon`, che pero'
registra soltanto `universalObjectCratesClasses`:

```neon
parameters:
    universalObjectCratesClasses:
        - Pest\Support\HigherOrderTapProxy
        - Pest\Expectation
```

In `vendor/pestphp/pest/` esiste un secondo file **non incluso**,
`phpstan-pest-extension.neon`, che registra
`Pest\PHPStan\HigherOrderExpectationTypeExtension`. Riguarda le higher-order
expectation: copre una parte del gruppo, quasi certamente non tutto — `$this`
indefinito e' un problema di binding dei closure, non di expectation.

**Quanta parte non e' stato possibile misurarlo.** La story deve misurarlo prima
di decidere. Non stimarlo.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. Il conteggio di `function.void` e `variable.undefined` su `analyse Modules`
   e' misurato con il solo `extension.neon` attuale — baseline riproducibile.
2. Il conteggio e' rimisurato includendo anche `phpstan-pest-extension.neon`.
   La differenza e' registrata nella story, per identificatore.
3. Se la differenza non azzera il gruppo, la story documenta **cosa resta e
   perche'**, ed enumera le opzioni con il costo di ciascuna. Sono ammesse:
   configurare il binding dei closure, oppure restringere l'analisi dei test.
   **Non e' ammesso** aggiungere `ignoreErrors`.
4. Nessun file di test viene modificato per far sparire una segnalazione di
   questo gruppo: se `$this` e' indefinito per PHPStan ma definito a runtime, il
   difetto e' nella configurazione, non nel test.
5. Ogni modifica proposta a `laravel/phpstan.neon` e' **proposta al maintainer,
   non applicata di iniziativa**.
6. La misura e' fatta con `analyse Modules` completo e zero errori
   `phpstan.parse`: un bootstrap fallito produce zero segnalazioni e sembra un
   successo.

## Dev Notes

<!-- LOCKED. External dev tools must not edit Dev Notes. -->

- **Il bootstrap che fallisce e' indistinguibile dal successo.** `phpstan
  analyse` che non parte esce con codice diverso da zero e nessuna riga di
  errore. Ogni misura di questa story deve verificare `totals.file_errors`
  insieme all'assenza di `phpstan.parse`, non fidarsi del conteggio.
- **`extension.neon` e `phpstan-pest-extension.neon` sono due file diversi
  nello stesso pacchetto.** Il primo e' incluso, il secondo no. Che il secondo
  esista non implica che sia la soluzione: implica che vada misurato.
- **Story 5.14 tratta lo stesso tema** (`pest-phpstan-plugin`). Se dopo la
  misura le due si sovrappongono, collegarle — non cancellare ne' rinumerare
  nessuna delle due.

## Testing

```bash
cd laravel

tmp=$(mktemp -p . phpstan-probe-XXXXXX.neon)
# includere phpstan-pest-extension.neon nel file temporaneo, mai in phpstan.neon
./vendor/bin/phpstan analyse Modules -c "$tmp" --no-progress --error-format=json --memory-limit=6G > /tmp/con-ext.json
rm -f "$tmp"
cmp -s phpstan.neon <(git show HEAD:phpstan.neon) && echo "phpstan.neon intatto"
```
