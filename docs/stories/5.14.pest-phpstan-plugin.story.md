# Story 5.14: Pest PHPStan — plugin ufficiale

## Story

Come **manutentore quality gate**,
voglio **`pestphp/pest-plugin-phpstan` installato e attivo**,
così **PHPStan capisce `expect()` generico, le catene higher-order e le regole Pest-aware**
invece di segnalare `method.internalClass` su ogni matcher.

Fonte: <https://pestphp.com/docs/phpstan>.

## Acceptance Criteria

1. `pestphp/pest-plugin-phpstan` e `phpstan/extension-installer` in `Modules/Xot/composer.json` require-dev.
2. `laravel/composer.json` non riceve dipendenze Pest — solo `allow-plugins.phpstan/extension-installer`.
3. Verifica funzionale: su `ProgressioniTest.php` compaiono identifier `pest.*` (non solo `method.internalClass`).
4. Documentazione in `wiki/concepts/pest-phpstan-plugin.md`.
5. `laravel/phpstan.neon` non modificato dagli agenti — cleanup duplicati documentato per l'utente.

## Tasks

- [x] aggiungere pacchetti a Xot `require-dev`
- [x] abilitare `phpstan/extension-installer` in root `allow-plugins`
- [x] `composer update` — plugin v5.0.2 installato
- [x] verifica con config senza duplicati (`pest.expectation.redundant`, `Expectation<T>`)
- [x] documentazione

## Esito verifica (2026-08-19)

Su `Modules/Progressioni/tests/Unit/Models/ProgressioniTest.php`:

- **Prima** (solo `pest/extension.neon` base): errori `method.internalClass` su `expect()->toBe*()`.
- **Dopo** (`pest-plugin-phpstan` via extension-installer): type `Expectation<Progressioni>`, regole
  `pest.expectation.redundant`, `pest.test.emptyClosure` — **16 errori semantici Pest**, zero internalClass.

## Azione utente (phpstan.neon)

Con `extension-installer` attivo, le righe manuali in `includes:` duplicano le estensioni e PHPStan
esce con warning + exit 1 **senza analizzare**. Rimuovere da `laravel/phpstan.neon` le righe già
caricate dall'installer (dettaglio in [pest-phpstan-plugin.md](./wiki/concepts/pest-phpstan-plugin.md)).
